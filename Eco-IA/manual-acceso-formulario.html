¿Cómo funciona el control de acceso?

El formulario Eco Interpretador usa una lista de correos autorizados dentro del propio archivo HTML. Cuando alguien inicia sesión con Google, el sistema verifica si su correo está en esa lista. Si está → accede al formulario. Si no está → ve una pantalla de acceso bloqueado.

Para agregar o quitar usuarios solo hay que editar una línea del archivo interpretacion.html y publicar el cambio en GitHub.

Cómo agregar un nuevo usuario

1
Abre el archivo en VS Code
En tu proyecto de GitHub Pages, abre el archivo interpretacion.html que está en la carpeta raíz del sitio (excelentia.com.mx/interpretacion.html).
2
Busca la línea de correos autorizados
Usa Cmd + F (Mac) o Ctrl + F (Windows) y busca exactamente:
ALLOWED_EMAILS
Vas a encontrar una línea que se ve así:
const ALLOWED_EMAILS=['fernando.davila.olvera@gmail.com','fdavila@excelentia.com.mx',...];
3
Agrega el nuevo correo
Dentro de los corchetes [ ], añade el nuevo correo entre comillas simples seguido de una coma. Ejemplo: quieres agregar a doctor.nuevo@gmail.com:
// ANTES:
const ALLOWED_EMAILS=[
  'fernando.davila.olvera@gmail.com',
  'fdavila@excelentia.com.mx',
  'acabrera@excelentia.com.mx',
  'jjcabrera@excelentia.com.mx',
  'ecointerpretador@gmail.com'
];

// DESPUÉS:
const ALLOWED_EMAILS=[
  'fernando.davila.olvera@gmail.com',
  'fdavila@excelentia.com.mx',
  'acabrera@excelentia.com.mx',
  'jjcabrera@excelentia.com.mx',
  'ecointerpretador@gmail.com',
  'doctor.nuevo@gmail.com'
];
⚠️ Importante: el correo debe ir en minúsculas, exactamente como el usuario lo tiene registrado en Google. Una mayúscula o un espacio de más bloquea el acceso.
4
Guarda el archivo
Guarda con Cmd + S (Mac) o Ctrl + S (Windows).
5
Publica el cambio en GitHub
En la terminal de VS Code ejecuta estos tres comandos uno por uno:
git add interpretacion.html
git commit -m "Agrega acceso a doctor.nuevo@gmail.com"
git push
✅ En menos de 60 segundos el cambio estará en producción. El nuevo usuario ya puede entrar al formulario.
➖

Cómo quitar el acceso a un usuario

1
Sigue los pasos 1 y 2 de la sección anterior
Abre el archivo y busca ALLOWED_EMAILS.
2
Elimina la línea del correo que quieres bloquear
Borra toda la línea con ese correo, incluyendo la coma del final. Ejemplo: quitar a doctor.nuevo@gmail.com:
const ALLOWED_EMAILS=[
  'fernando.davila.olvera@gmail.com',
  'fdavila@excelentia.com.mx',
  'acabrera@excelentia.com.mx',
  'jjcabrera@excelentia.com.mx',
  'ecointerpretador@gmail.com',
  'doctor.nuevo@gmail.com'
];
⚠️ Asegúrate de que el correo anterior a la línea eliminada no quede con coma al final si es el último. El último correo de la lista no lleva coma.
3
Guarda y publica
Igual que antes:
git add interpretacion.html
git commit -m "Revoca acceso a doctor.nuevo@gmail.com"
git push
✅ El usuario verá la pantalla de "Acceso no autorizado" la próxima vez que intente entrar.
⚠️

Errores comunes y cómo evitarlos

!
El correo tiene mayúsculas
Siempre escribe el correo en minúsculas. Aunque Google lo muestre con mayúsculas, el sistema siempre compara en minúsculas.
// ❌ Mal:
'Doctor.Nuevo@Gmail.com'

// ✅ Bien:
'doctor.nuevo@gmail.com'
!
Falta o sobra una coma
Cada correo —excepto el último— necesita una coma al final. Si falta una coma, o si el último correo tiene coma, el formulario dejará de funcionar para todos.
// ❌ Mal (falta coma en la segunda línea):
'fdavila@excelentia.com.mx'
'acabrera@excelentia.com.mx',

// ✅ Bien:
'fdavila@excelentia.com.mx',
'acabrera@excelentia.com.mx',
!
El usuario no cierra sesión antes de probar
Si acabas de agregar a alguien y dice que sigue bloqueado, pídele que cierre el navegador completamente y vuelva a entrar. El token de Google se queda en caché unos minutos.
